# Инструкция для агента: отчёт «COO Hub · Радар» на данных витрины

**Кому:** агенту внутри корпоративного контура с доступом на чтение к витрине COO Hub (Greenplum).

**Результат:** один файл `coo_hub_ГГГГ-ММ.html` для исполнительного директора, отчёт проверок `coo_hub_ГГГГ-ММ_check.md` и короткое сообщение человеку, который дал задачу.

## Что это за страница

Ежемесячная сводка для очень занятого руководителя.

- **Радар:** все метрики на одном кольце, в центре — сколько в красной зоне.
- **«Где болит»:** карточки с поручениями.
- **«Продукты»:** карта юнитов с провалом внутрь.
- **Список метрик:** карточки с графиком по месяцам.

Страница уже готова: код, стили и шрифты лежат в `page/template.html`, как она должна выглядеть — видно в `page/example_page.html`. Всё окрашивание страница считает сама по порогам из данных.

**Твоя задача — только данные:** выгрузить из витрины, привести к формату `DATA_FORMAT.md`, проверить и встроить в шаблон. Код страницы не меняй.

## Комплект

```
README.md                 эта инструкция
DATA_FORMAT.md            формат данных страницы: поля, правила, пример
page/template.html        страница без данных — одна метка /*__COO_HUB_DATA__*/null
page/example_page.html    та же страница с вымышленными данными — так должен выглядеть результат
data/example_data.json    полный пример данных (21 юнит × 13 метрик, вымышленные)
data/minimal_example.json короткий пример (3 юнита × 2 метрики) — удобно читать
sql/coo_hub_export.sql    разведочные запросы и основной запрос к витрине
tools/make_page.py        одна команда: выгрузка → данные → проверка → страница
tools/mart_to_json.py     конвертер выгрузки в формат страницы (его вызывает make_page.py)
tools/coohub_config.json  настройки конвертера: вариант метрики, подписи, откуда брать численность
tools/validate_data.py    проверка любого data.json по формату
tools/embed_data.py       встраивание data.json в шаблон
```

Инструментам нужен только Python 3.8+ без сторонних библиотек. В сеть они не ходят.

## Перед началом — спроси у человека, не угадывай

1. Полное имя витрины: `схема.таблица`.
2. Отчётный месяц.
3. После шага 1: какой вариант `metric_option` показывать, если у метрик их несколько. Это вкладки дашборда «Фокусные юниты / Юниты с включёнными целями / Все юниты» — решение по смыслу, его принимает человек.

## Шаг 1. Разведка — один раз

Выполни шаги 0.1 и 0.2 из `sql/coo_hub_export.sql`, подставив имя витрины вместо `<coo_hub_mart>`.

- **0.1 — как записано «итого по всем сотрудникам».** Обычно колонки `emp_*` и `seniority*` пустые. Если там слово («Все», «ALL»), добавь его в `total_tokens` в двух местах: в `params` основного запроса и в `tools/coohub_config.json`.
- **0.2 — варианты метрик.** Если у метрики несколько `metric_option` или `data_type`, покажи список человеку и впиши его выбор в `tools/coohub_config.json`:
  ```json
  "variants": {"*": {"metric_option": "Все юниты"}}
  ```
  Выбор можно задать и для отдельной метрики — ключом служит её русское название.

## Шаг 2. Выгрузка

Выполни основной запрос из `sql/coo_hub_export.sql`, указав в `params` отчётный месяц — первое число, например `date '2026-09-01'`. Сохрани результат в CSV: UTF-8, с заголовком. Разделитель любой, XLSX тоже подойдёт.

- **Формат выгрузки — «длинный».** Одна строка = месяц × юнит × метрика. Окно — прошлый год целиком и текущий по отчётный месяц. Плюс строки разреза по сегменту сотрудников (HQ / Line / Support) — только за отчётный месяц.
- **Колонки** — ровно те, что в `SELECT`, названия не меняй. Если в витрине колонка называется иначе, пропиши соответствие в `columns` конфига.
- **Проверь число строк.** Сравни его в файле с запросом 0.3. Инструменты выгрузки (Superset, DBeaver) могут молча обрезать результат по лимиту.

## Шаг 3. Сборка

### Путь А — есть Python (основной)

```
python3 tools/make_page.py выгрузка.csv --month 2026-09
```

В `out/` появятся три файла:

- `coo_hub_2026-09.html` — страница;
- `coo_hub_2026-09.json` — данные в формате `DATA_FORMAT.md`;
- `coo_hub_2026-09_check.md` — отчёт проверок.

Если в отчёте есть ошибки, страница не собирается. Каждая ошибка говорит, что поправить: исправь конфиг или выгрузку и запусти снова. Флаг `--force` соберёт черновик `_draft` только для отладки — директору его не отдают.

### Путь Б — собираешь данные сам

Если конвертер не подходит — нет Python или данные приходят не из этой выгрузки, — собери JSON строго по `DATA_FORMAT.md`. Ориентир — `data/minimal_example.json` и `data/example_data.json`. Дальше:

```
python3 tools/validate_data.py data.json     # 0 ошибок — можно встраивать
python3 tools/embed_data.py data.json        # проверит ещё раз и соберёт coo_hub_ГГГГ-ММ.html
```

Если Python нет совсем, встрой вручную:

1. Открой `page/template.html` как текст.
2. Найди единственное вхождение `/*__COO_HUB_DATA__*/null`.
3. Замени его на JSON, в котором `</` заменено на `<\/`.
4. Сохрани как `coo_hub_ГГГГ-ММ.html` в UTF-8.

Страница сама проверяет структуру данных при открытии. Если что-то не так, вместо отчёта будет список проблем, а не пустой экран.

## Шаг 4. Проверка перед сдачей

- [ ] `validate_data.py` пишет «можно встраивать» — это делают и `make_page.py`, и `embed_data.py`.
- [ ] В `_check.md` ноль ошибок. Предупреждения выписаны для человека.
- [ ] HTML открыт в браузере и всё на месте:
  - [ ] радар с числом в центре и вердиктом;
  - [ ] «Где болит»;
  - [ ] карта «Продукты» — плитки нажимаются и проваливаются внутрь;
  - [ ] «Все метрики»;
  - [ ] нет экрана «страница не может показать эти данные»;
  - [ ] в консоли нет ошибок.
- [ ] Сверка с Superset: таблица «Сверка с Superset» из `_check.md` — хотя бы пять строк, по одной из каждого блока и все красные. Они должны совпадать с дашбордом COO Hub за тот же месяц на верхнем уровне. Нет доступа к Superset — попроси сверить человека.
- [ ] Файл называется `coo_hub_ГГГГ-ММ.html`, без `_draft`.

## Шаг 5. Что отдать человеку

1. `coo_hub_ГГГГ-ММ.html`.
2. `coo_hub_ГГГГ-ММ_check.md`.
3. Сообщение в 5–8 строк:
   - период и дата актуальности данных;
   - что директор увидит на первом экране — первая строка раздела «Что директор увидит на первом экране»;
   - предупреждения;
   - результат сверки;
   - решения, которые ты принял или которые принял человек: вариант метрики, скрытые метрики, корень дерева.

## Правила

- **Данные не покидают контур.** Выгрузку, JSON и HTML нельзя загружать во внешние сервисы, внешние репозитории и внешние ИИ.
- **Код страницы не менять.** В `page/template.html` меняется только метка данных. Если что-то не так со страницей, опиши проблему человеку.
- **Ничего не выдумывать.** Нет значения — `null`, нет порога — `null`. Нельзя подставлять ноль или среднее.
- **Проценты — от 0 до 100. Изменения — разности, а не прошлые значения.** Это две самые частые ошибки.
- **Директору не отдают** черновик `_draft`, файл с ошибками проверки и файл без сверки с Superset.
- **Решения по смыслу принимает человек:** вариант метрики, какие метрики скрыть, какой юнит считать корнем.

## Если что-то пошло не так

| Что видишь | Что сделать |
|---|---|
| «метрика лежит в нескольких вариантах» | Показать варианты человеку, вписать выбор в `variants` конфига |
| «не нашёл ни одной строки итого» | «Итого» записано словом — добавить его в `total_tokens` конфига и запроса |
| «нет обязательных колонок» | Сверить `SELECT` с запросом из комплекта или прописать `columns` в конфиге |
| «ровно N строк — похоже на обрезку» | Выгрузить без лимита строк |
| «строк за отчётный месяц заметно меньше» | Витрина за месяц не догружена — уточнить у человека, ждать ли |
| «несколько строк с разными значениями» | Есть ещё одна колонка-вариант — добавить её в `variant_columns` конфига и выбрать значение в `variants` |
| «похоже на доли», «пороги похожи на доли» | Путь Б: умножить проценты и пороги на 100 |
| «mom_value_final похоже на прошлое значение» | Путь Б: записать разность `value_final − прошлый месяц` |
| «Корней … нужен ровно один» | Добавить общий корень «Все юниты» (см. `DATA_FORMAT.md`) |
| На странице «страница не может показать эти данные» | Запустить `validate_data.py`, исправить по списку |
| На iPhone в предпросмотре почты видна только надпись про браузер | Нормально: открыть файл в Safari («Поделиться → Открыть в…») |

## Настройки `tools/coohub_config.json`

| Ключ | Зачем |
|---|---|
| `variants` | Какой вариант `metric_option` / `data_type` показывать |
| `total_tokens` | Как в витрине записано «итого по сотрудникам», если не пустыми колонками |
| `report_month` | Отчётный месяц, если не последний в выгрузке (или флаг `--month`) |
| `headcount` | Откуда брать численность юнита. По умолчанию — знаменатель «Недорабатывающих» |
| `root_rk`, `max_depth` | Показать поддерево каталога, отрезать глубокие уровни |
| `metrics_include`, `metrics_exclude` | Какие метрики показать и в каком порядке |
| `metrics` | Подписи (`unit_num`, `unit_den`, `gap_tpl`) и поправки, если витрина отдаёт что-то не так |
| `blocks` | Короткое имя нового блока для кольца и фразы вердикта |
| `meta.disclaimer` | Гриф в подвале страницы |

Всё, чего нет в конфиге, конвертер определяет сам и пишет в отчёт, что решил. Проверь это в разделе «Что витрина показала о себе».
