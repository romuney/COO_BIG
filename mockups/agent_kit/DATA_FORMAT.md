# Формат данных страницы «COO Hub · Радар»

Страница читает один объект — `window.DATA`. В `page/template.html` для него ровно одно место:

```html
<script>window.DATA = /*__COO_HUB_DATA__*/null;</script>
```

Встроить данные — значит заменить `/*__COO_HUB_DATA__*/null` на JSON-объект, описанный ниже. Кодировка UTF-8, JSON может быть в одну строку. Внутри JSON замените `</` на `<\/`: иначе строка вида `</script>` из данных сломает страницу. `tools/embed_data.py` делает всё это сам и заодно проверяет данные.

Полный пример — `data/example_data.json`: 21 юнит × 13 метрик, цифры вымышленные. Короткий — `data/minimal_example.json`: 3 юнита × 2 метрики, он же в конце этого документа.

## Общая схема

```
{
  "meta":        { … },                    отчётный месяц, подписи, корень дерева
  "blocks":      { "goals": "Цели и достижения", "hr": "…", "it": "…" },
  "block_order": [ "goals", "hr", "it" ],  порядок блоков на кольце и в списке (необязательно)
  "block_meta":  { … },                    короткие имена и фразы блоков (необязательно)
  "units":       [ { … }, … ],             каталог юнитов — дерево
  "metrics":     [ { … }, … ],             метрики с порогами
  "facts":       { "<rk юнита>": { "<eng метрики>": { … } | null } }
}
```

## meta

| Поле | Тип | Обяз. | Что это | Пример |
|---|---|---|---|---|
| `period_label` | строка | да | Подпись периода | `"Сентябрь 2026"` |
| `business_month` | `"ГГГГ-ММ-01"` | да | Отчётный месяц | `"2026-09-01"` |
| `actual_data_dt` | `"ГГГГ-ММ-ДД"` | да | На какую дату данные: максимум `actual_data_dt` в витрине | `"2026-10-03"` |
| `n_fact` | 1…12 | да | Номер отчётного месяца, он же длина массивов `cur` | `9` |
| `year` | целое | да | Год отчётного месяца | `2026` |
| `months` | 12 строк | да | Короткие имена месяцев | `["янв", …, "дек"]` |
| `root` | строка | да | `functional_unit_rk` корня дерева | `"u0"` |
| `source` | строка | да | Источник, в подвале | `"Витрина COO Hub, Greenplum"` |
| `disclaimer` | строка | да | Гриф в подвале | `"Данные витрины на 03.10.2026. Для служебного пользования — не пересылайте за пределы компании."` |
| `title` | строка | нет | Заголовок вкладки | `"COO Hub · Сентябрь 2026"` |
| `owner`, `product`, `aggr_type`, `real`, `generated_at` | — | нет | Служебные, страница их не показывает | |

## blocks, block_order, block_meta

- **`blocks`** — `{ключ: название}`. Ключ берётся из `source_metrics_block`: латиница, цифры, `_`. Название — из `source_metrics_block_ru`.
- **`block_order`** — порядок блоков на кольце радара и в списке метрик. Если его нет, берётся порядок ключей в `blocks`.
- **`block_meta`** — `{ключ: {nick, ring, phrase: {red, amber, ok}}}`, необязательно. Для `goals`, `hr`, `it` в странице уже есть «Цели», «Люди», «Инфраструктура» (на кольце — «IT»). Для других блоков имя берётся из названия блока.
  - `ring` — подпись на кольце, до 9 символов.
  - `phrase` — части вердикта: `red` — «Цели буксуют», `amber` — «Цели на грани», `ok` — «цели в норме». `ok` пишется со строчной: эта фраза стоит в середине предложения.

## units — дерево каталога

| Поле | Тип | Обяз. | Откуда в витрине | Что это |
|---|---|---|---|---|
| `functional_unit_rk` | строка из латиницы, цифр, `_.:-` | да | `functional_unit_rk` | Идентификатор. Число записывайте строкой: `"12345"` |
| `functional_unit_nm` | строка | да | `functional_unit_nm` | Название |
| `parent_functional_unit_rk` | строка или `null` | да | `parent_functional_unit_rk` | Родитель; `null` только у корня |
| `leaf` | `true`/`false` | да | — | `true` только у юнита без детей в этом списке |
| `headcount` | число ≥ 0 или `null` | да | знаменатель «Недорабатывающих» | Численность — площадь плитки на карте. `null` — плитка средней площади, без подписи «чел.» |
| `lvl_unit` | целое | нет | `lvl_unit` | Уровень в каталоге витрины |
| `depth` | целое | нет | — | Глубина от корня, у корня 1. Показывается в выборе юнита |

Правила:

- Корень ровно один, и его `rk` записан в `meta.root`.
- Все родители есть в списке, циклов нет.
- Порядок — обход дерева от корня: юнит, затем его дети, затем их дети. В этом порядке идёт список «Чей месяц смотрим?». Детей удобно сортировать по `headcount` по убыванию.
- Если в витрине несколько верхних юнитов, добавьте общий корень `{"functional_unit_rk": "all", "functional_unit_nm": "Все юниты", "parent_functional_unit_rk": null}`. Его факты: у долей — сумма числителей детей / сумма знаменателей, у счётчиков — сумма.

## metrics

| Поле | Значения | Обяз. | Откуда в витрине | Что это |
|---|---|---|---|---|
| `eng` | `[a-z0-9_]` | да | `metric_name_eng_lower` | Ключ метрики |
| `name` | строка | да | `metric_name` | Название |
| `block` | ключ из `blocks` | да | `source_metrics_block` | Блок |
| `type` | `1` / `2` | да | `metric_type` | 1 — абсолютная (штуки, рубли, FTE); 2 — доля = числитель / знаменатель |
| `vt` | `"perc"` / `"int"` / `"real"` | да | `value_type` | Как печатать значение. **perc — проценты от 0 до 100, не доли** |
| `change` | `"up"` / `"down"` | да | `change_type` | Какое изменение хорошее: красит «к прошлому месяцу» и «к прошлому году» |
| `red`, `yellow` | число или `null` | да | `threshold_red`, `threshold_yellow` | Пороги в тех же единицах, что значения: у perc — тоже 0…100. `null` — порогов нет |
| `tdir` | `"up"` / `"down"` | да | из пары порогов | `up`: хорошо выше, красная зона ниже (красный < жёлтого). `down`: наоборот (красный > жёлтого) |
| `ttype` | `"value"` / `"mom"` | да | `threshold_type` | `value`: с порогом сравнивается значение. `mom`: изменение к прошлому месяцу в процентах, `25` = рост на 25% |
| `threshold_scope` | `"any_level"` / `"unit_level"` | да | правило ниже | `any_level`: порог применим к любому юниту. `unit_level`: порог конечного юнита, агрегат не красится, а показывает «N из M юнитов за порогом» |
| `desc` | строка | нет | `metric_desc` | «Как считается» |
| `cta` | строка | нет | `call_to_action` | «Что сделать» — из этого поля собирается поручение |
| `unit_num`, `unit_den` | строки | нет | подписи | «18 из 40 целей»: `unit_num` = «целей связаны», `unit_den` = «целей» |
| `gap_tpl` | строка с `{n}` | нет | подпись | Разрыв до жёлтого порога словами: «связать ещё {n} целей». Только для долей |

Как страница красит (для понимания; считать самому не нужно):

- `tdir = "up"`: значение < `red` — красная зона, < `yellow` — жёлтая, иначе норма.
- `tdir = "down"`: значение > `red` — красная, > `yellow` — жёлтая, иначе норма.
- `ttype = "mom"`: сравнивается 100 × (значение − прошлый месяц) / |прошлый месяц|.
- `threshold_scope = "unit_level"` у агрегата: если хоть один конечный юнит внутри в красной зоне — «пробито внутри», иначе норма.

## facts — значения

`facts[rk][eng]` — объект на каждую пару юнит × метрика. Если за отчётный месяц данных нет — `null`, **а не 0**: ноль — это значение, и страница честно его покрасит.

| Поле | Тип | Обяз. | Что это |
|---|---|---|---|
| `value_final` | число | да | Значение за отчётный месяц в единицах страницы: у perc — 0…100 |
| `value_numerator`, `value_denominator` | число или `null` | да | Числитель и знаменатель за отчётный месяц, как в витрине. У долей нужны: из них «18 из 40 целей» и разрыв до порога |
| `cur` | массив длины `n_fact` | да | Январь…отчётный месяц текущего года, пропуск — `null`. Последний элемент = `value_final` |
| `prev` | массив из 12 или `[]` | да | Январь…декабрь прошлого года, пропуск — `null`. `[]`, если прошлого года нет |
| `mom_value_final` | число или `null` | да | **Изменение** к прошлому месяцу: `value_final − прошлый месяц`. В январе прошлый месяц — `prev[11]`. У perc — в п.п. |
| `yoy_value_final` | число или `null` | да | **Изменение** к тому же месяцу прошлого года: `value_final − prev[n_fact − 1]`. `null`, если базы нет |
| `yoy_known` | `true`/`false` | да | `true`, если у метрики есть данные прошлого года и `prev[n_fact − 1]` не `null` |
| `cuts` | объект или `null` | нет | Только у конечных юнитов: `{"oper": {"label": "Сегмент", "parts": [{"name": "HQ", "num": 5, "den": 0}, …]}}`. У долей `num`/`den` — числитель и знаменатель части, у счётчиков `num` — значение, `den` — 0 |
| `thr` | `[красный, жёлтый]` или `null` | нет | Порог именно этого юнита, если он не такой, как у метрики; `null` — у юнита порога нет. Если порог как у метрики, поле не пишется |

## Как получить из витрины

Строки берутся такие:

- `aggr_type = 'M'`;
- «итого» по сотрудникам — все колонки `emp_*` и `seniority*` пустые;
- один вариант `metric_option` / `data_type` на метрику — его выбирает человек.

Основной запрос — `sql/coo_hub_export.sql`. Правила сборки ниже; `tools/mart_to_json.py` выполняет их все:

1. **Проценты.** Если `value_final` хранится долей, то есть ≈ числитель / знаменатель, умножьте на 100 всё, что относится к метрике: значения, `cur`, `prev`, изменения и пороги-доли.
2. **Направление.** `tdir` берётся из пары порогов: красный < жёлтого — `up`, красный > жёлтого — `down`, равны — как `change`. Если в витрине задан только один порог, повторите его во втором.
3. **Область порога.**
   - Доли (`type = 2`) и пороги `mom` — `any_level`.
   - Счётчики (`type = 1`), у которых порог одинаковый на всех уровнях каталога, — `unit_level`.
   - Если у агрегатов свои, масштабированные пороги, — `any_level`, а пороги агрегатов пишутся в их `thr`.
4. **Изменения** считайте по ряду сами, не копируйте `mom_value_final` / `yoy_value_final` из витрины: что в них лежит — изменение или прошлое значение, — нужно проверить. Исключение — прошлого месяца в ряду нет: тогда восстановите изменение из колонки витрины.
5. **База прошлого года.** `yoy_known = false`, если в прошлом году у метрики все значения пустые или нулевые — например, метрика появилась в этом году.
6. **Численность.** `headcount` — `value_denominator` метрики «Недорабатывающие» за отчётный месяц. Нет — `null`.
7. **Разрезы.** `cuts` — строки отчётного месяца, где заполнен `emp_specialization_oper_code` (HQ / Line / Support), а остальные колонки разрезов пустые. Только для конечных юнитов.
8. **Пустые клетки.** Юнит без строки за отчётный месяц → `null` в `facts`, даже если история есть.
9. **Округление** — до 4 знаков после запятой, не грубее.

## Частые ошибки — их ловит `tools/validate_data.py`

- Доли 0…1 вместо процентов у `vt = "perc"`; пороги долями при значениях в процентах.
- В `mom_value_final` / `yoy_value_final` лежит прошлое значение, а не разность.
- 0 вместо `null` там, где данных нет.
- Последний элемент `cur` не совпадает с `value_final`; длина `cur` ≠ `n_fact`.
- `leaf = true` у юнита с детьми (или наоборот); родитель, которого нет в списке; два корня.
- `tdir` противоречит паре порогов.
- Идентификаторы с пробелами и кавычками: `functional_unit_rk` и `eng` попадают в разметку страницы.

## Минимальный пример

Файл `data/minimal_example.json` целиком. Здесь — всё, кроме фактов двух юнитов из трёх: они устроены так же.

Что здесь видно:

- **«Связанность».** Доля, новая в этом году: `prev = []`, `yoy_known = false`. Значение 45 — это проценты, 18 / 40 × 100.
