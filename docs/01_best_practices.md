# Лучшие практики exec-репортинга: что берём в Exec Board

Синтез исследования (сырые заметки с источниками — в `docs/research/`). Цель — не пересказать книги, а вытащить правила, которые меняют дизайн нашего ежемесячного обзора для исполнительного директора, и показать, где каждое правило применено в макете.

## 1. Amazon: WBR-дек, шестистраничная записка и MBR

**Что делает Amazon (Working Backwards, гл. 6; Commoncog; WBR App).**

- Еженедельно S-Team смотрит 400–500 метрик за 60 минут. Это возможно только потому, что **все графики одной формы, в одном порядке каждую неделю**: «zero cognitive load — мозг занят информацией, а не форматом».
- Стандартный график **6-12**: слева последние 6 недель крупно, справа 12 месяцев; бледная линия прошлого года; цели — маркерами; максимум три ряда на графике. Под графиком **box score**: последний период, WoW, YoY, MTD, QTD, YTD.
- Дек отвечает на три вопроса в строгом порядке: что испытали клиенты → как идёт бизнес → идём ли по плану. Сначала **управляемые входные метрики**, потом выходные.
- Ревью — **по исключениям**: владелец говорит «nothing to see here», и все переходят к следующему графику. У каждой метрики один владелец; объяснения отклонений готовятся до встречи, импровизация запрещена, «не знаю, отвечу письменно к дате» — допустимо.
- **Анекдоты рядом с метриками**: страница Voice of Customer; правило Безоса «когда данные и анекдоты расходятся, обычно правы анекдоты — вы измеряете не то».
- Дек статичен и печатается: «переключение между владельцами — меньше двух секунд»; живые дашборды на встрече недопустимы.
- Метрики регулярно пересматривают; после каждого сюрприза спрашивают «что мы могли бы отслеживать, чтобы это не повторилось?»
- **6-pager**: полные предложения вместо буллетов, потому что «нарратив заставляет понять, что важнее чего и как связано»; читают молча 20 минут в начале встречи; FAQ заранее отвечает на спорные вопросы; приложение может быть сколь угодно длинным.
- **MBR (месячный обзор)** — нарратив до 6 страниц + таблицы в приложении, одна и та же структура каждый месяц: метрики → объяснение результатов → прогресс инициатив → организация.

**Что берём.**

| Правило | Где в макете |
|---|---|
| Одна форма графика для всех метрик, один порядок каждый месяц | Стр. 02 «Панель управления»: 15 плиток одной формы; вариант A в макете вариантов |
| Текущий год против прошлого + план/цель/лимит на одном графике | Каждая плитка панели; график траектории на стр. 03 |
| Box score: значение, м/м, г/г, к плану | Строка дельт в плитке; box score в варианте A |
| Ревью по исключениям, статусы «требует решения / наблюдаем / по плану» | Стр. 01 «Сигналы месяца»; статусы плиток; вариант C |
| Один владелец и заранее написанный комментарий | Поле «Владелец» в каждой плитке; блок «Комментарий» на каждой странице |
| Нарратив в полных предложениях, читаемый молча | Три абзаца на стр. 01; вариант B; комментарий на каждой странице |
| FAQ: вопросы директора с ответами владельцев | Вариант B «Вопросы и ответы владельцев»; блок «О чём спросить» на каждой странице |
| «Что могли бы отслеживать?» | Раздел «Бэклог» в каталоге метрик |
| Статичный документ, печатается | Все страницы верстаются в A4 landscape (`@media print`) |

**Что не берём.** Еженедельный ритм (у нас месяц), 400 метрик (у нас 15 на панели и ~60 в разделах), чисто монохромный дек без текста (см. сравнение вариантов).

## 2. Стандарты визуализации: IBCS, Few, Tufte

**IBCS (SUCCESS).** SAY — сообщение, а не тема, в заголовке каждой страницы; UNIFY — одна нотация для сценариев (факт — сплошная тёмная, прошлый год — серая, план — пунктир/контур, прогноз — штрих); CONDENSE — плотность вместо воздуха; CHECK — одинаковые шкалы, столбцы от нуля; EXPRESS — никаких «спидометров», пирогов, радаров; STRUCTURE — MECE.

**Stephen Few.** Дашборд — «один экран, чтобы понять, когда нужно действовать»; каждая цифра — с контекстом (план, прошлый год, тренд); точность до уровня решения ($3,8M, а не $3 848 305); подсветка только при пересечении порога, «никаких вечно горящих светофоров»; один цвет тревоги, интенсивность — серьёзность; форма + цвет для дальтоников.

**Edward Tufte.** Спарклайны — «графики размером со слово» внутри текста и таблиц; малые множества с общей шкалой; **слопграф** для сравнения структуры на две даты (читается и как рейтинг, и как изменение); data-ink; «одна большая таблица лучше ста маленьких графиков»; подписи событий прямо на графике.

**Что берём.**

| Правило | Где в макете |
|---|---|
| Заголовок страницы — сообщение с глаголом (IBCS SAY, Minto) | Все заголовки: «HQ идёт по плану, но воронка найма выведет за лимит…» |
| Нотация сценариев: факт / прошлый год / план / лимит | Легенда «Как читать» на стр. 02; одинаковые стили во всех графиках |
| Столбцы от нуля; обрыв оси помечен | Стеки и бары от нуля; мосты — с меткой «≈» на оси |
| Слопграфы для структуры на две даты | Стр. 06 «Сдвиги» — 20 срезов |
| Спарклайны в тексте и таблицах | Вариант B; скоркарта профессий; блок «Стабильно» |
| Тепловая заливка одной краской в таблицах, цифры остаются | Скоркарты профессий, сегментов, управляемости |
| Подсветка только по порогу; серый — по умолчанию | Статусы плиток и KPI; «Без изменений» без цвета |
| Мосты (waterfall) с итогами и сходимостью | Стр. 03: мост YTD и прогнозный мост к лимиту |

## 3. Управленческая отчётность: Minto, board packs, management by exception

- **Answer first.** Пирамида Минто: вывод наверху, аргументы ниже; заголовки-сообщения, по которым можно прочитать всю историю. У нас: заголовок каждой страницы + три абзаца на стр. 01.
- **Board Intelligence / ICSA.** Директора тратят на пакет 3–4 часа независимо от объёма и читают ~30 страниц в час; 68% оценивают материалы как слабые; главные претензии — слишком длинно, не про будущее, слишком операционно. Правило QDI: начинать с вопроса, на который должен ответить читатель, затем решение, затем контекст. У нас: страницы 01–02 читаются за 10 минут; разделы 03–10 — по запросу; блок «Решения, которые ждут».
- **Management by exception (Тейлор, 1911).** Руководителю — «только сжатые, сравнительные отчёты, в которых выделены исключения — и особенно плохие, и особенно хорошие». У нас: «Сигналы месяца» показывают и красное, и зелёное.
- **Сколько метрик.** Parmenter 10/80/10, Kaplan-Norton 20–30, практики Power BI/Domo 5–9 на экран. Наш выбор: 15 метрик на панели (с группировкой), 3–5 в фокусе на стр. 01, остальное в разделах.
- **Сигнал против шума (Wheeler, XmR).** Флаг должен срабатывать на исключительную вариацию, а не на любой месячный скачок. У нас правила порогов описаны в `02_concept.md` и предполагают коридоры / тренды из 3+ месяцев, а не одиночные отклонения.
- **Grove (High Output Management).** Парные индикаторы (эффект и контрэффект) — например, Refresh 5% всегда рядом с regrettable-текучестью; «стаггер-чарт» прогнозов — как менялся прогноз конца года от месяца к месяцу. У нас: пара refresh/regrettable на стр. 05; стаггер прогноза — в бэклоге.

## 4. Executive people boards: что показывают CEO/COO в лучших компаниях

- Типовой набор (Workday, Visier, Bersin, ISO 30414): численность к плану/лимиту; найм и вакансии (time-to-fill, acceptance, aging); текучесть — годовая, regrettable, ранняя; внутренняя мобильность и промо; структура (span, layers, % руководителей); вовлечённость/менеджерская эффективность; риски и навыки; ИИ-адопшен.
- **Мост численности** как основная форма контроля лимита: открытие → найм (новые / замены) → переводы → уходы → закрытие, плюс «обязательства» (принятые офферы + вакансии) и **landing forecast** к концу года. Именно так построена стр. 03.
- **Определения.** Годовая текучесть = ушедшие за 12 мес. / средняя численность (не «месяц × 12»); regrettable — добровольный уход того, кого хотели удержать (правило: топ-перформер или незаменим за 6 мес.); недоукомплектованность = вакансии / (вакансии + численность) — конвенция BLS JOLTS; time-to-fill — от открытия заявки до принятого оффера; просроченные — старше 90 дней.
- **Бенчмарки для контекста** (см. `research/03`): добровольная текучесть в США 13% (Mercer 2025), европейский tech 15–17% (Ravio); acceptance офферов ~84% (Ashby/Gem 2025); time-to-fill 39 дней non-exec (SHRM 2026), инженерные роли 50–62; конверсия стажёров 63% (NACE 2026); span: player-coach 3–5, coach 6–7, supervisor 8–10 (McKinsey), 6–8 для инженерных ролей (Bain); Google сократил на 35% руководителей с командой < 3; Amazon поднял IC:manager на 15%.
- **ИИ-адопшен как воронка** с фиксированными определениями: покрытие (доступ) → активные за 28 дней → регулярные (≥ 2–3 дня в неделю) → power-пользователи (несколько раз в неделю и > 30 мин экономии в день, определение Microsoft WTI). У нас: покрытие / WAU / power на стр. 09.
- **Цифровые следы** (встречи, переработки) — только агрегаты с минимальным размером группы; политика использования данных — на самой странице. Этика — самая частая причина провала таких проектов (Insight222: 81%).
- **Не строить один «индекс здоровья организации»**: композиты скрывают движение и требуют раскрытия весов (OECD). Показывать 3–4 компонента рядом. У нас: панель из 15 метрик вместо индекса.

## 5. Двадцать правил для нашего Exec Board

1. Ответ первым: заголовок каждой страницы — предложение с выводом.
2. Одна форма графика и один порядок метрик каждый месяц.
3. Ни одной «голой» цифры: факт всегда с прошлым годом и планом/целью, плюс тренд.
4. Нотация сценариев едина: факт, прошлый год, план, прогноз, лимит.
5. Изменения показываем явно (м/м, г/г, к плану) и красим по смыслу, а не по знаку.
6. Одинаковые шкалы для одинаковых единиц на странице; столбцы от нуля.
7. Время слева направо, структура сверху вниз.
8. Никаких спидометров, пирогов, второй оси; таблица + спарклайн вместо десяти графиков.
9. На панели 10–15 метрик, 3–5 в фокусе; остальное в разделах и приложении.
10. Подсветка только по порогу; серый по умолчанию; хорошие исключения тоже показываем.
11. Порог — из вариации ряда (коридор, 3+ месяца тренда), а не «любое отклонение».
12. Всё серое, один акцент — там, где смысл страницы.
13. Сравнение сегментов — малыми множествами с общей шкалой.
14. Структура на две даты — слопграф; смесь во времени — стек только когда смесь и есть сообщение.
15. Мосты численности с итогами и обязательной сходимостью.
16. Точность до уровня решения; числа выровнены по правому краю; воздух вместо рамок.
17. Самое важное — вверху слева; один и тот же элемент на одном и том же месте каждой страницы.
18. Комментарий рядом с графиком, а не на отдельной странице; у каждого исключения владелец, вопрос и срок.
19. Комментарий объясняет, а не описывает, и смотрит вперёд: причина, изменение прогноза, нужное решение.
20. Документ для чтения, а не для показа: самодостаточные страницы, 10 минут на первые две.
